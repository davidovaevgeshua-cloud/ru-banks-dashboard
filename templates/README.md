# Шаблоны квартальных МСФО-отчётов

Когда выходит новая отчётность и нужно обновить дашборд, скачайте датабук с IR-страницы банка и заполните один из этих шаблонов. Пришлите заполненный файл в чат Perplexity — я вставлю числа в payload, пересчитаю форвардные мультипликаторы и закоммичу.

## Что выбрать

- **quarterly_report.json** — один банк, один квартал. Удобно, если банк один или отчёты приходят в разное время. Скопируйте под каждый банк отдельно.
- **quarterly_report.csv** — несколько банков в одной таблице. Удобно закинуть 2–3 отчёта, вышедших близко по времени (например, Совкомбанк + БСПБ в один день).

## Как заполнять

- Все денежные показатели — **в млрд рублей**.
- Все проценты — **числом без %**: `22.5`, а не `22.5%` и не `0.225`.
- Пустые/неизвестные поля — `null` (в JSON) или пустая ячейка (в CSV). Я подтяну недостающее из предыдущего квартала либо пересчитаю.
- Даты — в формате `YYYY-MM-DD`.
- Тикеры — как в дашборде: `SBER`, `VTBR`, `T`, `DOMRF`, `SVCB`, `BSPB`, `MBNK`.

## Что я делаю с этим файлом

1. Обновляю квартальные ряды (`net_income_parent_ltm`, `nim_q`, `cir_q`, `equity_parent`, `assets` и т.д.) — добавляю точку на `publication_date`.
2. Пересчитываю LTM-мультипликаторы (`pe_ltm`, `pb_ltm`, `ptbv_ltm`, `roe_ltm`) от новой чистой прибыли/капитала и текущей цены.
3. Если в `forward_updates` есть новые NI/EQ — обновляю прогноз, иначе оставляю прежний из `_fwd_const`.
4. Если в `dividends` есть новая рекомендация — добавляю в `divs[TK]` и в форвардную таблицу за соответствующий год.
5. Обновляю `last[TK].period` = `period_end`.
6. Обновляю `state/reports_last_seen.json`:
   - `seen[TK]` = новый `quarter` (чтобы уведомления про этот же квартал больше не приходили).
7. Коммичу в репо → GitHub Pages деплой автоматически подхватывает.

## Пример

См. `EXAMPLE_svcb_2026q1_filled.json` — реальные числа Совкомбанка за 1К2026, взятые из текущего payload дашборда.

## Какие поля обязательные

Обязательный минимум для нормального обновления:

- `ticker`, `quarter`, `period_end`, `publication_date`
- Одно из двух: либо `ltm.net_income_parent_ltm` (готовое LTM из презентации), либо `quarterly.net_income_parent_q` (я сам суммирую)
- `balance.equity_parent` — для P/B

Всё остальное улучшает качество дашборда, но не критично.
